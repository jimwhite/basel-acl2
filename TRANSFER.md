# ACL2(r)-to-ACL2 transfer: contract and trust boundary

This project uses ACL2(r) to prove a rational finite-sum bound, then imports
that result into ordinary ACL2 so the remaining arithmetic proofs can run
there. The transfer is deliberately limited to a checked event interface.
It is not a general ACL2(r) book importer, a verified transfer theorem, or a
proof that arbitrary ACL2(r) results are valid in ordinary ACL2.

## How the transfer works

Everything is done by certifying ACL2 books. No intermediate file is
generated by either side.

1. **Export (ACL2(r)).** An export book, as `r2a-import` requires, contains
   exactly

   ```lisp
   (in-package "ACL2")
   (include-book "transfer")
   (r2a-export NAME EVENT ...)
   ```

   with no other events. `r2a-export` computes the portable interface of
   `EVENT ...` (described below) and rejects the export if it is not
   portable. It then proves the original events, including their analytic
   local helpers. After that, it rechecks that the world has no trust tags,
   skipped proofs, redefinition or added axioms, and records the interface
   in the `r2a-exports` table. See
   [`basel-export.lisp`](basel-export.lisp) and
   [`example-export.lisp`](example-export.lisp).

2. **Import (ordinary ACL2).** A client book calls
   `(r2a-import "<export book>")`. Ordinary ACL2 reads that same source
   file and requires the export-book shape above. It then derives the
   interface with the same `transfer` code and checks it again before
   admitting it. See [`basel-import.lisp`](basel-import.lisp) and
   [`example-import.lisp`](example-import.lisp).

The two systems therefore agree on the interface by construction, not by
comparing an artifact. `export-tests` additionally asserts that the
importer's reading of each export book equals the interface that ACL2(r)
recorded. A source file containing a `#+` or `#-` reader conditional is
rejected, because the two systems could read it differently.

A retained (non-`local`) `(include-book "x")` in an export must name a
sibling book in the same directory, without options. The importer reads
that book, projects and checks its events as part of the interface, and
then includes it natively. A `local` include, such as the analytic
[`basel-analytic.lisp`](basel-analytic.lisp), is proof-only and is not
read by the importer. For Basel, `basel-analytic` uses `make-event` to read
the upstream ACL2(r) `nonstd/basel/basel-series.lisp`, up to the lemma it
needs, from the system books. Its expansion is stored in the certificate.

Ordinary ACL2 and ACL2(r) both write `.cert` files for the shared books, so
the two sides must certify in separate directories. The supported commands,
which copy the sources to `build/acl2r/` and `build/acl2/` and run `cert.pl`,
are:

```sh
scripts/acl2r-certify.sh   # basel-export example-export export-tests transfer-tests
scripts/acl2-certify.sh    # basel-interval demo example-import import-tests transfer-tests
```

Books for only one flavor are marked with the community `cert_param`
comments `(uses-acl2r)` or `(non-acl2r)`. Importing books, and the books
that include them, have a `.acl2` file containing

```lisp
; cert-flags: ? t :ttags ((:acl2r-checked-transfer))
```

which `cert.pl` passes to `certify-book`. The list form `((:tag))` allows
the tag in any number of books (see `:doc defttag`). A client that includes
an importing book must also allow the tag, for example
`(include-book "basel-interval" :ttags ((:acl2r-checked-transfer)))`.

## What is checked and transferred

There are two event streams:

- The **source proof** runs normally in ACL2(r). It may use analytic
  definitions, nonstandard analysis, and local proof helpers.
- The **portable interface** is the event sequence retained by
  `r2a-export`. Its definitions and theorem statements are
  checked against the supported ordinary-ACL2 vocabulary before transfer.

Local events outside nontrivial encapsulates are omitted from the interface,
including locals inside trivial encapsulates. The source proof still has to
admit and prove the original events normally. Inside a nontrivial
encapsulate, the full event subtree is retained and checked, including local
witnesses and nested scopes. Proof hints are discarded during export.

This distinction allows analytic helpers to support the source proof without
being introduced into ordinary ACL2. It does not allow an unchecked helper
to appear in a retained definition, theorem formula, or encapsulate witness.
After a nonempty encapsulate, constrained functions and definitions from its
scope are not added to the vocabulary for subsequent exports. This avoids
treating an abstract function's ACL2(r) existence assumptions as ordinary
ACL2 facts.

The supported interface is intentionally small:

- `defun` with an ordinary body, optionally with one
  `(declare (xargs :measure ...))`. The receiving ACL2 proves termination.
- `defthm`, optionally with source `:hints` and `:rule-classes`. The imported
  theorem receives `:rule-classes nil`.
- `local` and nested `encapsulate`.
- `(include-book "x")` of a sibling book, whose own projected events are
  checked as part of the interface (see above).
- Nonempty encapsulate signatures of the form `((f (x ...) t) ...)`, with a
  direct local `defun` witness for each signature function.

The term checker allows a limited, explicit set of arithmetic and list
operations, predicates, basic macros, and earlier portable definitions. It
handles `QUOTE`, `LET`, and `LET*` explicitly. Unsupported forms, arbitrary
macros, named constants, and non-ordinary-ACL2 data are rejected. In
particular, the interface does not allow other `include-book` forms,
`make-event`,
`defmacro`, `defconst`, `defchoose`, `defun-sk`, `defun-std`, `defaxiom`,
`skip-proofs`, or raw Lisp.

## Trusted events and trust obligations

For each imported theorem, the importer creates a local trusted clause
processor accepting only the clause derived for that theorem, with explicit
supporters and tag `:acl2r-checked-transfer`. Definitions are admitted
normally. The auxiliary predicates, processors, and supporting facts are
local, so they cannot outlive the local definitions on which they rely.

Ordinary ACL2 does not recheck the ACL2(r) proof. It trusts that the named
export book certifies in ACL2(r) with the same `transfer` code. Run
`scripts/acl2r-certify.sh` on the same sources before relying on an import.
The export-book shape keeps other events from influencing the source proof.
The trust obligation covers the source checker, the event generator, the
ACL2(r) certification of the export book, and the correspondence of
definitions across the two systems. Do not populate the `r2a-exports` table
manually.

## Why the restrictions matter

An ACL2(r) theorem can depend on irrational witnesses even when its
conclusion looks rational. For example, a local witness that defines a
function as `(sqrt 2)` cannot safely be treated as an ordinary ACL2
definition. The checker rejects this case and aliases through
nonportable definitions; it does not infer safety from the theorem's
operators alone.

Abstract functions are another hazard. In ACL2(r), an encapsulate
constraint may be justified by an irrational witness; ordinary ACL2 may not
be able to satisfy the same constraint. Retaining and checking the local
witnesses is therefore essential, and the post-encapsulate vocabulary
restriction prevents later transfers from relying on an unsound
interpretation of the abstraction.

All of `transfer` is in `:logic` mode with verified guards, and it uses
no trust tags of its own. Termination of every function is proved,
including the include-book expansion. That expansion fails closed after
`*r2a-max-include-depth*` nested books. Execution cannot leave the guard
domain, so no part of the checker or generator relies on unchecked raw Lisp
behavior. The code avoids `:program` system functions such as `translate`
and `extend-pathname`. Free variables come from a small proved-terminating
term walker. If that walker is wrong, the generated predicate either fails to
be admitted or fails to match the theorem, and the import is rejected. The
book also proves the vocabulary policy as theorems:

- `r2a-termp-applies-only-vocabulary`: an accepted term applies only the
  reviewed operators and the supplied portable functions.
- `r2a-local-exports-nothing`: a `local` event adds no function to the
  vocabulary.
- `r2a-nontrivial-encapsulate-keeps-vocabulary`: an encapsulate with
  signatures leaves the vocabulary unchanged.

Logic mode does not make the trusted clause processors sound by itself, and
the following trust remains:

- The transfer argument is semantic. The reviewed operators agree on ordinary
  ACL2 objects in both systems and are closed over them. A checked formula
  true in every ACL2(r) model is therefore true over the ACL2 universe.
  A trusted clause processor formally promises provability in the receiving
  ACL2 theory. Bridging that gap is a conservativity claim that this project
  argues but does not prove.
- The importer does not verify that the export book was certified in
  ACL2(r). It checks only the book's shape and interface. Certifying with
  `scripts/acl2r-certify.sh` first is part of the trust obligation. A future
  hardening is to check the ACL2(r) certificate.
- Some operators, such as `rfix`, have different definitions in the two
  systems that agree on ordinary ACL2 objects. Extending the operator list
  requires the same agreement check.

Extending the syntax or changing the abstract-function policy requires a new
soundness review and regression tests.

For this Basel development, the transferred theorem bounds a finite odd
reciprocal-square sum using rational endpoints. The analytic source helpers
remain in ACL2(r); the ordinary ACL2 partial-sum bounds, telescoping
estimates, and executable interval are proved on the receiving side. See
[Adapt ACL2r Proof.md](Adapt%20ACL2r%20Proof.md) for the mathematical
derivation and [VALIDATION.md](VALIDATION.md) for the tested results.
